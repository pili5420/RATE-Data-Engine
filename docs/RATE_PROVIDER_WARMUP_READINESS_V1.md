## Trust and isolation

run_provider_warmup_readiness.py requires an externally trusted feature-manifest
SHA, original Producer Base/Head/checkout, exact universe source/hash/commit,
independently pinned protected-file inventory, and new execution Base/Head.
It does not self-pin an untrusted manifest. The original Producer is replayed in
a separate read-only, network-denied process because original plans pin absolute
parser paths. No old Producer or source binding is changed. The new calculation
then reconstructs the existing core and reports its original content identity.

Fresh external output only; never a closed source root, repository, Production,
Latest, State, Portfolio, Ledger or snapshots path. Parent audit enforcement
allows writes only within this output, and source replay allows no writes at all.
Source and all tracked old/new checkout files are hash-checked before/after.
Independent --cold-read with --expected-result-sha256 repeats source-owner replay,
recomputes the four gates and checks the persisted envelope. Generation/validation
times are separate from stable core identity and original observation times.

No scheduler, first refresh, publication, active EPS provider, scoring or portfolio
API is called. Do not infer a real account checksum if no account path was
supplied: process-level write denial and unchanged existing tracked owners prove
non-interference without reading private account contents.
